# VS-001 — Discussion to AI-Proposed Task

Status: In Progress
Version: 0.1
Started: 2026-08-10

## Objective

Validate the core Cadence architecture through one end-to-end user journey:

Login
→ Project Workspace
→ Discussion
→ Team Agent task proposal
→ Human confirmation
→ Task creation
→ Audit trace

## Architectural Rules

1. PostgreSQL/Supabase is the authoritative state store.
2. Authentication and Cadence authorization remain separate.
3. Browser clients do not perform authoritative cross-module writes.
4. Each module owns its state.
5. Team Agent never writes directly to Tasks.
6. Protected commands enforce RBAC server-side.
7. Material writes produce versioned domain events.
8. AI-generated state requires provenance.
9. Human confirmation does not bypass target-module permissions.
10. Correlation IDs trace the complete operation.
11. Retryable commands must be idempotent.
12. Changes affecting contracts are recorded in CHANGELOG.md.

## Acceptance Scenario

Given an authorised project member posts:

"Daniel, please finalise the syllabus by Friday."

Cadence shall:

1. Store the human message and version.
2. Emit MessageCreated.v1.
3. Create an AI run.
4. Create a pending task proposal.
5. Allow an authorised human to review the proposal.
6. Revalidate agent.approve.
7. Revalidate task.create.
8. Revalidate task.assign when an assignee is specified.
9. Create one authoritative task.
10. Record provenance to the originating proposal/message.
11. Emit TaskCreated.v1.
12. Make the task visible through GET /me/tasks.
13. Reconstruct the complete action through one correlation ID.

## VS001-02 — Authentication and Identity

Status: Complete

### Implemented

- Supabase Auth adapter.
- Bearer JWT validation.
- Cadence identity resolution.
- Disabled-user rejection.
- Shared RequestContext creation.
- Request and correlation ID handling.
- Support for caller-supplied valid X-Correlation-ID.
- GET /api/v1/me.

### Verified

- Missing Authorization header returns 401 UNAUTHENTICATED.
- Invalid JWT returns 401 UNAUTHENTICATED.
- Valid Supabase identity without Cadence mapping returns 401 UNAUTHENTICATED.
- Valid Supabase identity mapped to a disabled Cadence user returns 401 UNAUTHENTICATED.
- Valid Supabase identity mapped to an active Cadence user returns HTTP 200.
- GET /api/v1/me returns the expected Cadence user fields.
- Authentication failures do not expose internal account state to callers.
